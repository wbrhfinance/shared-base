The starting point

A token is the unit an LLM bills for. Not a word, not a character.

The mechanics

Modern LLMs break text into recurring subword fragments using byte-pair encoding. The model bills each fragment it processes.

  • 1 token ≈ 4 English characters ≈ 0.75 words. 100 words is roughly 130 tokens.
  • Input tokens are what the model reads: prompt, files, prior chat history.
  • Output tokens are what the model generates back.
  • Output costs 2 to 8 times input across providers. Median ratio 4 to 5 times.

The wrinkle: vendors count differently

The same English text gets a different token count depending on the tokenizer used. The tokenizer is part of the product, not neutral infrastructure.

Anthropic shipped Claude Opus 4.7 with a tokenizer that encodes up to 35% more tokens for the same English text than its predecessor. An effective price hike with no list-price change.

Practical consequence: you cannot compare vendors purely on dollars-per-token. The same task costs different absolute amounts to run.

A working decision framework

Four variables determine what any LLM call costs.

Before reaching for a rate card, hold these four in mind. Each one moves the bill independently. Stack them badly and a routine task can cost 50 to 100 times its floor.

1

Language

English is the cheapest baseline. French and German typically cost 50-60% more tokens for the same content.

2

Model

Haiku < Sonnet < Opus on cost and depth. The price spread between tiers is 5× on input.

3

Workflow

Chat < research < deep research / agentic. Each tier multiplies token consumption by 5-10×.

4

History & output length

Long chats and long answers are hidden cost multipliers. Output costs 4-6× input.

Best practice playbooks · by user type

CAPE has two user populations. Each needs a different cost discipline.

Population A · Web-based

Subscription users on Claude.ai, ChatGPT, Perplexity

On a flat monthly fee with rate-limited usage windows. For security reasons, CAPE restricts desktop-app access to specific employees today.

  • Goal: maximise useful work per session window
  • Cost lever: rate-limit headroom, not dollar savings
  • The win: more productivity per subscription
Population B · Full-suite / pay-as-you-go

API users, Claude Code, Cursor, MCP integrations, automated pipelines

Effectively uncapped usage. Per-token metering applies directly. This is where the bill actually accumulates and where governance matters.

  • Goal: cost per unit of useful work
  • Cost lever: real dollar savings via architecture and routing
  • The risk: blind sign-off on "unlimited" usage

The winning play

The teams that win on AI cost over the next 12 months are those who route intelligently and cache aggressively.

Route

Send the right query to the right model

Most enterprise traffic does not need a frontier model. A simple classifier or rule routes routine queries to Haiku or a budget model and escalates only when reasoning depth requires it.

  • 80% of typical traffic can run on budget models with no measurable quality loss
  • Documented 47-80% spend reduction in production environments
  • Cheapest implementation: tag your tasks by type, hard-code the model mapping
Cache · what it actually is

Stop paying to re-read the same content

Prompt caching stores the model's internal computation of a repeated prefix (system prompt, document, instructions). The next call reuses it. The model still sees the prefix; you pay a fraction.

  • OpenAI: automatic for prompts ≥1,024 tokens. 50% off cached input.
  • Anthropic: explicit cache_control. Read at 10% of input rate.
  • Google: explicit caching. Read at $0.20/M vs $1.25/M standard.
  • Production research: 41-90% reduction on input-token cost from caching alone

Routing without caching captures 60-70% of the prize. Caching without routing captures 40-60%. The two stacked, with batch on top, hits the 80-95% reductions documented in production.

In conclusion · what's coming

Claude pricing: confirmed near-term changes, May 2026.

For individuals · capacity up, list prices unchanged
  • Claude Code rate limits doubled for Pro, Max, Team, and Enterprise plans.
  • Peak-hours degradation removed for Pro and Max accounts.
  • API rates unchanged for Opus, Sonnet, Haiku at time of review.
  • Net effect: more useful work per subscription this quarter, no per-token cost change.
For enterprise · pricing restructured
  • Moving to a seat-plus-consumption model.
  • Lower headline seat prices, but explicit token-usage commitments attached.
  • For organisations with variable demand, this can increase effective cost and reduce flexibility.
  • Anthropic is monetising the enterprise channel more aggressively as IPO pressure rises.

Subscription users gain headroom this quarter. Enterprise procurement gets harder. Plan accordingly: the rules in this deck need to become habit before the next pricing cycle, not after.
